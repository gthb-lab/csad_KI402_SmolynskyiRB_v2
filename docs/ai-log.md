## 2. Помилки та їх виправлення

### Помилка 1. Файли агента створено поза репозиторієм
- **Симптом:** `git add -A && git commit` повідомив «nothing to commit, working tree clean», хоча файл відображався в редакторі.
- **Причина:** у VS Code була відкрита батьківська папка, а не папка репозиторію; `.github/` створився поруч із репозиторієм.
- **Виправлення:** каталог `.github` перенесено в репозиторій, VS Code відкрито на папці репозиторію; `git status` почав бачити файл.
- **Висновок:** перед кожним запитом перевіряти `git rev-parse --show-toplevel`.

### Помилка 2. Застарілі назви інструментів у manifest
- **Симптом:** агент не підхоплювався належним чином.
- **Причина:** у першому запиті було вказано `tools` у вигляді `codebase`, `editFiles`, `runCommands`, які не відповідають актуальній документації VS Code.
- **Виправлення:** запит 5: Copilot звірив формат із документацією VS Code і замінив їх на `search/codebase`, `search/fileSearch`, `edit/editFiles`, `execute/runInTerminal`.

### Помилка 3. Prompt-команди не відображалися в чаті
- **Симптом:** `/init`, `/check` та інші команди не з'являлись у Copilot Chat.
- **Причина:** за відповіддю Copilot, VS Code завантажує `.prompt.md` лише в Local harness, а не в Copilot harness.
- **Виправлення:** запит 5: prompts отримали явні імена з суфіксом `-local` (`git-init-local`, …, `init-local`), для Copilot harness додано 6 skills-обгорток з `user-invocable: true`. Основні skills залишились три: `project-scaffold`, `build-and-test`, `github-actions`.
- **Наслідок:** у чаті оркестратор запускається як `/init-local`, перевірка як `/check-local` (відповідність файлів і команд описана в `docs/architecture.md`).

### Помилка 4. Збіг назви `/init` із вбудованою командою Copilot
- **Симптом:** `/init` створив `.github/copilot-instructions.md` (запити 6 і 11) замість запуску нашого оркестратора.
- **Причина:** назва збігається з вбудованою командою Copilot.
- **Виправлення:** оркестратор запускається як `/init-local` (або через Chat: Run Prompt); згенерований файл не включається до репозиторію.

### Помилка 5. Перший `/check` завершився помилкою (очікувано)
- **Симптом:** запит 7: підсумок «ПОМИЛКА», бракувало `src/`, `tests/`, `requirements.txt`, `ci.sh`, `ci.bat`, `.gitignore`, `.gitattributes`, `ci.yml`.
- **Причина:** `check` запущено до `init-local`.
- **Рішення:** після `/init-local` повторна перевірка пройшла (запити 9, 13, 16). Це підтвердження, що `check` реально виявляє відсутні файли, а не завжди повертає PASS.

### Помилка 6. Порожня вкладка Actions
- **Симптом:** на GitHub вкладка Actions показувала «Get started».
- **Причина:** workflow запускається за `push`/`pull_request` для `develop` і `master`, а `push` у `feature/hello-python` його не запускає.
- **Виправлення:** відкрито PR `lab1/finish` (`feature/hello-python` → `develop`), після чого CI запустився на трьох ОС.

### Спостереження 7. Тимчасовий файл у робочому каталозі
- `/check-local` (запит 16) повідомив про untracked `ci-output.txt` (збережений вивід `ci.bat`). Файл не потрібен у репозиторії, тому його не додавали до коміту.

## 3. Прийняті та відхилені рішення

- **Прийнято:** суфікс `-local` для назв prompt-команд через збіг із вбудованою `/init`; файли залишаються `*.prompt.md`.
- **Прийнято:** додаткові skills-обгортки для Copilot harness; три основні skills збережено.
- **Прийнято:** зміну в `init.prompt.md`, яка узгоджує виклики кроків із `name` у frontmatter prompts.
- **Прийнято:** PyInstaller для створення виконуваного `hello`. <за потреби вкажіть погодження з викладачем>
- **Прийнято:** CI запускається через PR на `develop`; тригери workflow не змінювалися.
- **Відхилено:** додавання `feature/**` до тригерів `push`, щоб CI не залежав від PR (методичка вимагає `develop` і `master`).
- **Відхилено:** комітити `ci-output.txt` і `.github/copilot-instructions.md`.
